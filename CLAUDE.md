# Autoporada

Weekly management-meeting ("Porada vedení školy") app for a Czech school: Czech UI, generates the DOCX. Stack: Next.js 16, React 19, TypeScript strict, Zod 4, Drizzle on PostgreSQL 18, pg-boss 12, Vitest, Playwright. This Next.js has breaking changes: read `node_modules/next/dist/docs/` before writing Next code.

## Commands (pnpm)

- `pnpm dev:services` starts Postgres, Mailpit, mock IdP, Gotenberg (compose.dev.yaml); `dev:services:down` stops them.
- `pnpm dev` (web), `pnpm dev:worker` (worker), `pnpm db:migrate` (= `pnpm cli migrate`), `pnpm dev:seed` (dev accounts Ředitel and Učitelka, see README), `pnpm cli <command>` (reads `.env`); `pnpm cli jobs:run <job> [key]` queues one cron job now (an unknown name prints the jobs).
- `pnpm build`; `pnpm build:node` bundles `dist/worker.mjs` (and the CLI) with esbuild.

## Gate before calling work done

```
pnpm -s typecheck && pnpm -s lint && pnpm -s lint:arch && pnpm -s lint:unused && pnpm -s lint:chars && pnpm -s format:check && pnpm -s test:all
```

Then, when the change warrants it:

- `pnpm test:e2e`: needs dev services up and port 3100 free. Its global setup runs `dist/worker.mjs`, which must not be older than `src/`, so run `pnpm build:node` first. Never run it together with `check-deploy.sh`. `m10-generate.spec.ts` runs in its own `generate` project after `desktop` and `mobile` (a generation publishes every approved point).
- `pnpm test:render` needs `dev:services` (Gotenberg, poppler-utils); not part of the gate.
- Docker checks: build the web, worker and tools images as `:check` (commands in the header of `scripts/check-deploy.sh`), then `pnpm -s lint:compose`, `scripts/check-web-image.sh autoporada-web:check` and `scripts/check-deploy.sh` (needs ports 80 and 443).

## Layers (enforced by `.dependency-cruiser.cjs`; changing a rule means updating ADR 0004)

`src/`: `domain` (pure, imports only domain; `report` and `people` hold points and the people memory) <- `snapshot`, `contracts`, `notify` (zod + domain only) <- `document` (compose, model, render-docx, render-html) <- `application` (core, ports, use-cases, jobs, notifications; no I/O) <- `infra` (implements ports; a leaf). Edges and composition roots: `server` (container.ts binds infra), `app` (route handlers and the minimal shell `layout.tsx`, `not-found.tsx`, `global-error.tsx`; reaches server only via `server/routes/index.ts`), `ui` (only `ui/copy`, the Czech sentences Arch, the shell and the server share; imports only contracts, domain, zod), `worker/main.ts`, `cli/main.ts`. `infra/directory` is the school people search (a port with `off`, `dev` and `graph` adapters). `infra/convert` is the Gotenberg adapter: the worker's DOCX-to-PDF on `gotenberg` (network `render`, worker only) and the web's `.doc`-to-PDF for the annex import on a separate, locked-down `gotenberg-import` (network `import`, web only; `GOTENBERG_IMPORT_URL`; `POST /api/arch/convert`, ADR 0066). `lint:compose` pins both networks.

- Cross-module imports go through `index.ts` only.
- Only infra imports drizzle, pg, pg-boss, openid-client, jose; only `infra/mail/smtp.ts` imports nodemailer (`nodemailer-only-in-smtp`).
- `web-never-sends-mail`: server/app never reach infra/mail, infra/worker, application/jobs or nodemailer, even transitively. The web only enqueues.
- `worker-isolated`: worker never imports server, app or ui.
- `use-cases-not-into-jobs`: use cases enqueue via application/notifications, never import application/jobs.
- `src/instrumentation-client.ts` imports only zod (it sets zod jitless before hydration; ADR 0023, `instrumentation-client-is-light`).
- `docx` only in `document/render-docx`; `.tsx` only in `app` and `document/render-html`.
- No circular imports, no orphans, no `test/` imports from `src/`.

## Conventions

- Two test worlds: Vitest `unit` runs against in-memory fakes (`provide: world=fake`), `integration` runs the same suites against PostgreSQL (`world=pg`, a database per test file). Port contracts live in `test/contract` and run in both worlds; helpers in `test/support/world`.
- Every use case is in `USE_CASES` (`use-cases/index.ts`) and its folder's `index.ts`, with a colocated `.test.ts` (`test/arch/inventory.test.ts`). An export with no consumer fails knip, so land it with its first user.
- Rate limits (`server/routes/arch-run.ts`; the inventory pins its `AUTOSAVE` and `SUBMISSION` sets): `points.save` and `future.save` use `autosave` (120 a minute per user); create, submit, retract and withdraw use `submission`; decisions and reviewer edits use `admin`. An approved akce never autosaves: it changes only through `future.save` with intent `revise`. A non-vedení author cannot cancel an approved akce, only ask (`future.requestCancel`, take back with `retractCancel`); vedení `cancel`s or `refuseCancel`s (ADR 0062). The request is `future_items.cancel_requested_at` on an item that stays approved, not a state.
- `DIRECTORY=off` (default), `dev` (with `DIRECTORY_DEV_PATH`, e.g. `docker/dev/directory.json`) or `graph` (the web's own Entra registration, ADR 0021) switches the people search; `dev` is refused in production, and production stays `off` until SMOKE-TEST step 29 has run on the tenant. The people memory is the author's own points, with no table of its own.
- Timed jobs are the `CRON` entries in `application/jobs/cron.ts` (mail prune, report prompt, deadline reminders, late event reports (`reports.late`)); the reviewer digest, the headmaster summaries and the moved notice are switched off but keep their handlers (ADR 0037). A handler reconciles to the clock and the data, never to the tick, and the mail ledger key makes a rerun send nothing; the worker reads business tables only through narrow column grants (a new column it reads needs a grants migration; 0030, 0035 and 0046 added `settings(key, value)`, the late-report dates and `future_items.kind`). The worker has no grants on `registry_*`, `issue_items` or `report_placeholders`.
- Generation (ADR 0038–0041): `issues.generate` (Náhled, headmaster; blocked by the preflight `earlier-open` while an earlier porada is open: generate or drop it first) stores the DOCX in `generated_documents` and stages it in `pdf_sources`, publishes the points and queues `pdf.render`; the worker reads the DOCX only from `pdf_sources` and deletes it when the PDF settles. A trigger keeps a settled document unchangeable. No reopen or regenerate yet. Generation also marks each akce with a placeholder `missed` and withdraws its unapproved report point (ADR 0049); preflight `reports-missing` only warns. Downloads are same-site GETs on the `/porada/[datum]/dokument/{docx,pdf}` routes (`archive.view`, audited), linked as plain anchors with no `download` attribute (it would save the failure redirect as a file; ADR 0045). A failed download 303s to `/#/archiv?chyba=<kind>`; a cross-site one to `/#/archiv` and a signed-out one to `/` (ADR 0065). `generated_documents.pdf_failure` (why the PDF failed) is written by the worker through a column grant.
- Akce reports (ADR 0046, 0048, 0049, 0056, 0061): every approved akce owes a report (no `expects_report`, no decline; a jednání never does). The report goes to the akce's porada (`owedPorada` in `domain/calendar/reminders.ts`; assembly and preview go through `application/core/report-window.ts`), not by hand-in time; `points.submit` refuses `report-not-due` when that porada is generated. A report not approved by generation prints as a placeholder paragraph built from the typed texts (a refused one prints nothing and closes its akce); the headmaster edits it on Arch's `#/porada/zpravy` (`issues.setPlaceholder`, `admin` limit, table `report_placeholders`) and confirms it with `issues.confirmPlaceholder` (`admin` limit; ADR 0061). It is checked iff `report_placeholders.confirmed_original` equals the system paragraph now (`domain/review/placeholder.ts`). Unchecked ones only warn: preflight `placeholders-unchecked` plus a client-side confirm dialog; the server never refuses. `src/server/routes/arch-placeholders.ts` builds `placeholderChecks` for the headmaster. `IssueRepo.lock` (non-bumping row lock) is taken by generate and setPlaceholder: take it after the deadline rule.
- Report grammar (ADR 0067): no report types; `titleGender` (`domain/cs/sentence`) reads gender from the title, unknown prints „akce „…““; every report starts with `REPORT_BULLETS` (`domain/report`).
- Free text (ADR 0060): akce and jednání have `organizer`, `participants` and `note`, shown as typed (Arch names the note `remark`, since its `note` is the return note); there is no structured responsible. The organizer has a role (ADR 0063, `organizerRole` `organizes|coordinates`, required on submit when names are typed); `organizerPhrase` (`domain/cs`) prints the verb, plural iff the names contain a comma, and a null role (older items) prints as typed and survives a revise that keeps the names. Return parts are title/when/place/who/note. The snapshot is schema 2; `src/snapshot/upcast-v1.ts` reads v1.
- Calendar (ADR 0054, superseding 0051 items 2–5 and 0047 item 3): a porada that does not take place does not exist. `issues` status is `open|generated`; setting `calendar` = `{ plannedThrough }` (not savable by `settings.save`, not shown). Up to the later of `plannedThrough` and last week's Monday the calendar is exactly its rows; after it a row-less Monday is a virtual porada (`calendarBoundary`). The Monday key (`slotMondayOf`) never changes. `issues.move {monday, meetingDate}` changes meeting date and deadline only, bounded by the neighbouring poradas. `issues.drop {monday, confirmed}` deletes the row, makes rows for the virtual Mondays before it and for its heir, raises `plannedThrough` to the heir and hands over outline, empty texts and Arch annexes. `issues.add {meetingDate}` adds a porada (one per week, `porada-exists`; `later-generated` refuses one before a generated porada). `planMove`, `planDrop`, `planAdd` (`domain/calendar/plan.ts`) decide and refuse, run by the use cases and by Arch's dialogs; calendar functions (`issueSlots`, `handInSlot`, `owedPorada`, …) take a required `plannedThrough`. The three take `settings.lock('deadline','update')`; `ensureIssue` is not-found for a row-less Monday up to the boundary. The archive lists generated poradas only. There is no `/profil` page or soft opt-out (ADR 0046); `settings.reminders` is the only switch.
- The deadline is a rule in `settings` (ADR 0032), counted back from the free `meeting_date`, not the slot (`issues.monday`, ADR 0034). Any code that writes an issue row first reads the rule under `settings.lock` (share lock; the deadline save takes the update lock). Registry rows hold no person ids (ADR 0033).
- Audit meta and logs never carry text people wrote (`test/arch/audit-meta.test.ts` scans `src/application`). Point bounds live in `domain/report/limits.ts` and feed Zod, the UI counters and the CHECK numbers.
- Errors and logs carry codes, never messages, addresses, subjects or provider text (ADR 0015, 0016); a database constraint outside `KNOWN_CONSTRAINTS` fails as `db.constraint.<name>` (ADR 0022).
- Errors name what failed (ADR 0044, 0045): `classifyFailure` (`application/core`) maps an exception to a `FailureCause` (`contracts/failure.ts`); a new cause needs its sentence in `ui/copy/failures.ts` and a row in the classifier's table test. `unavailable` carries `cause`, never a request id (that stays in logs and the `x-request-id` header). `src/app/global-error.tsx` is the last resort; sign-in failures land on `/?chyba=<kind>`, no `kod`. Development adds a `Technicky:` line through a describer that production never binds; never quote a database error's message.
- Czech UI copy lives in `src/ui/copy`. `lint:chars` forbids raw invisible or look-alike characters in `src`, `test/support`, `scripts`: write NBSP as `\u00a0`.
- Migrations: edit the Drizzle schema, run `pnpm db:generate`, never edit a committed migration. A data fix on an append-only table disables its no-update trigger inside the migration (0054).
- Commits: one per feature or fix, Conventional Commits, no AI or Co-Authored-By trailers. Run the gate first.
- The template `.docx` is never committed (only `test/fixtures/template/format-facts.json`, from `pnpm facts:extract <template.docx>`).
- Untracked `AGENTS.md` is rewritten by `next dev`; keep it uncommitted.

- Annex from a file (ADR 0066): the browser (`arch/core/import`, lazy chunks: mammoth, pdf.js, jszip) turns .docx/.odt/.pdf/.doc into ordinary annex parts (text without marks, tables, pictures); .pdf and .doc give text only. Nothing new is stored. `arch/build-real.mjs` builds ESM with splitting and copies `pdf.worker.min.mjs`; the CSP has `worker-src 'self'`; the import checks the whole annex list against `ANNEXES_MAX_BYTES` (`domain/report/limits.ts`) and zip sizes before inflating. `/api/arch/convert` (own `import` limiter, one in flight per process) takes 10 MB, `/api/arch/run` 4 MB (1 MB without `issue.edit`); both are outside the `src/proxy.ts` matcher, so Next does not buffer them.
- Arch UI (ADR 0053): `/` serves the client in `arch/` (built into `public/arch` by `pnpm build:arch`, part of `dev` and `build`), which reads `GET /api/arch/state` and writes `POST /api/arch/run`. Read `DESIGN.md` before changing it: the tokens, components, and the rules (style 1:1 with the prototype; backend changes allowed under the rules above). Its style follows the prototype, so `arch/` is outside Prettier; ESLint, `tsc -p arch` and knip (`lint:unused`, entry `arch/a/main.tsx`) still check it.
